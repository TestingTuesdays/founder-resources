# Structured data and entity markup QA

[← Skills](../README.md) · [Guide](../../design-growth/schema-markup-review.md)

## Inputs

Versioned website/app, core user task, audience, relevant source evidence and authorized testing environment.

## Steps

1. Choose supported type based on actual page content, not hoped-for rich result.
2. Use accurate Organization, SoftwareApplication, Product or Article only when applicable.
3. Verify URLs, names, prices, offers, author and dates against rendered content.
4. Avoid fabricated AggregateRating, FAQ or review markup.
5. Test syntax with official validators and monitor Search Console warnings.
6. Recheck after localization, pricing or product changes.

## Deliverable

Ranked issues with page, evidence, severity, recommended fix, owner, expected effect, release version and observed retest. Separate hypothetical improvements from measured results.

## Safety

No private data in public issues, no invented rankings, reviews or compliance claims, and no copying of protected design assets.
