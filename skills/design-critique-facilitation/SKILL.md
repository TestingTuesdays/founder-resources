# Structured design critique and prioritization

[← Skills](../README.md) · [Guide](../../design-growth/design-critique-facilitation.md)

## Inputs

Versioned website/app, core user task, audience, relevant source evidence and authorized testing environment.

## Steps

1. State user, task, design constraints and known research.
2. Ask reviewers to note observations separately from suggestions.
3. Group findings by hierarchy, content, accessibility, navigation and trust.
4. Rate impact and evidence strength; distinguish preference from task failure.
5. Select 1–3 changes with owner and expected user outcome.
6. Retest revised design with the same scenario.

## Deliverable

Ranked issues with page, evidence, severity, recommended fix, owner, expected effect, release version and observed retest. Separate hypothetical improvements from measured results.

## Safety

No private data in public issues, no invented rankings, reviews or compliance claims, and no copying of protected design assets.
