# Vulnerability disclosure and safe intake

[← Skills](../README.md) · [Guide](../../docs/security-disclosure-intake.md)

## Inputs

Versioned product, real target user task, synthetic test accounts, authorized environment and named reviewer.

## Procedure

1. Publish a monitored security contact and supported reporting scope.
2. Define authorized test boundaries and no-public-disclosure expectations.
3. Acknowledge report, restrict access and reproduce with synthetic data.
4. Classify impact, affected versions and temporary mitigations.
5. Coordinate fix, retest and responsible disclosure.
6. Review repeated patterns and incident escalation.

## Completion criteria

Evidence-backed issue register with observed outcomes, severity, owner, fix, build and retest. Separate hypotheses and proposed tests from executed tests.

## Privacy and safety

Never publish participant identities, payment details, credentials or unapproved security findings. Escalate regulated or safety-critical questions for expert review.
