# Design systems, components and design tokens — reusable skill

[← Skill library](../README.md) · [Detailed guide](../../design-growth/design-systems-tokens.md)

## Inputs

Live or staging URL, target audience, core user journey, representative devices, current product facts and authorized testing access.

## Procedure

1. Inventory typography, colors, spacing, radii, shadows and icon styles.
2. Create semantic tokens rather than page-specific magic numbers.
3. Specify button, input, card, navigation and dialog states including errors and disabled.
4. Test keyboard, contrast, focus, zoom, long translations and loading states.
5. Create representative component stories and visual regression baselines.
6. Document responsive rules and ownership before broad migration.

## Output

A prioritized audit: URL/component, problem, impact, evidence, recommended change, owner, expected outcome, verification status and comparable retest.

## Rules

No guaranteed rankings, fabricated testimonials, hidden SEO manipulation or unlicensed copied assets. Distinguish research from tested results. Use the [audit template](../../templates/design-growth-audit.md).
