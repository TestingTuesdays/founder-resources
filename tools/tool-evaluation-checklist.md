# Evaluate a testing tool before adopting it

[← Tools](README.md)

Score each item 0 (no evidence), 1 (partial), 2 (meets need). Do not add up scores mechanically when security or privacy is a hard blocker.

| Question | Score | Evidence |
| --- | --- | --- |
| Solves a measurable high-priority testing problem | | |
| Works with our tech stack and CI | | |
| Supports intended platforms/devices | | |
| Exportable raw results and no lock-in surprise | | |
| Transparent pricing, seats and overages | | |
| Data retention/redaction, access controls and region fit | | |
| Accessible dashboards and tester experiences | | |
| Easy to maintain and train contributors | | |
| Reliable support and documentation | | |
| Works with sample-sized pilot before annual commitment | | |

**Trial proof:** use two real workflows, document setup hours, execution effort, false positives, reporting quality and costs at projected scale. Never upload secrets or real customer data during trial setup without authorization and appropriate safeguards.
